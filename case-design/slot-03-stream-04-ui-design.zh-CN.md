# 界面 03 接入 120 秒案例设计

日期：2026-10-27。需求已确认，本文件完成接入设计；界面和后端代码尚未按此修改。

底部第三个按钮继续显示 **03**，实际播放 [stream-04.jsonl](../data/streams/stream-04.jsonl)。片段长度为 **120 秒**，比赛时钟覆盖 **90:00–92:00**。沿用现有球场、卡片、观众角色及个性化布局。

数据事实以 [120 秒案例设计](120s-counterattack-var-design.zh-CN.md) 和 [格式说明](stream-04-format.zh-CN.md) 为准。本设计不改变已生成的动作、轨迹或判罚时间。

## 2. 120 秒与两套时钟

片段长 120 秒。JSONL 的最后一帧发生在 120000 ms，正常到达延迟为 80 ms，因此最后记录在收件时钟 120080 ms 到达。这不构成额外 0.08 秒的比赛内容。

本例采用首帧预缓冲：加载发生于 0 ms、到达于 80 ms 的首帧后，以播放位置 0 ms 暂停。初始即显示完整 22 人与球，比赛时钟为 90:00。正向播放 120 秒后收件时钟到达 120080 ms，显示位置恰为 120000 ms。

| 字段 / 操作 | 本例约定 |
| --- | --- |
| `as_of_ms` | 继续表示收件观察时刻，所有记录仍同时受发生时间和到达时间限制 |
| 内部会话时长 | 保留最后到达时刻 120080 ms，用于排空记录 |
| `playback.duration_ms` | 120000，供界面进度条与播放结束判断使用 |
| `playback.receive_offset_ms` | 80，从本例首帧的到达时间减发生时间取得 |
| `playback.position_ms` | `clamp(as_of_ms - receive_offset_ms, 0, 120000)` |
| `playback.match_clock_ms` | `5400000 + playback.position_ms` |
| 界面进度条 | 0:00–2:00，最大值 120 秒 |
| 顶部比赛时钟 | 90:00–92:00，显示最低补时 `+2` |
| 界面拖动到 t 毫秒 | 向现有 `seek_ms` 接口提交 `t + receive_offset_ms` |
| 点击重播 / 回到开头 | 跳至收件时刻 80 ms，显示位置 0:00，比分 0–0 |
| 拖到结尾 | 跳至收件时刻 120080 ms，保留最后一帧，显示 2:00 / 92:00 |

`seek_ms` 的现有收件时钟含义保持一致；仅新案例的界面播放坐标做上述换算。旧案例没有 `playback` 扩展时继续使用原有路径，不套用本例的 80 ms 偏移。

例如，最终判罚发生在片段第 115 秒，收件时钟到 115080 ms 时才可见。此时界面播放位置是 1:55，比赛时钟是 91:55。直接按收件时刻检查 115079 ms 时，比分仍为 0–0。

统计窗口与可读的时间标签以片段播放时间为端点；记录可见性仍由 `as_of_ms` 控制。事件详情同时保留原始发生和获知时间，不能用显示时间覆盖 JSONL。

## 3. 页面呈现

### 比分牌

保留现有顶部比分牌，在时钟附近增加紧凑的比赛状态提示，不打开遮挡球场的大弹窗。

- 正常比赛：时间下方显示 `补时 +2`。
- 入网待判：琥珀色提示“入网待判”，比分仍为 0–0。
- 越位与 VAR：提示当前判罚、复核阶段，比分仍为 0–0。
- 最终确认：绿色提示“进球有效”，比分更新为 Atlas 0–1 Union。
- 片段结束：提示“片段结束 · 比赛尚未终场”，停在 92:00，比分保持 0–1。

状态必须同时有文字，不仅依靠颜色。窄屏上允许换行，不覆盖队名、比分或播放控件。

### 左下解说卡

正常比赛继续使用实时事实、所选球队与角色。发生入网、越位、复核和最终判罚时，解说卡优先呈现官方事实。

这类比赛级判罚对两队都可见，不能因为用户关注 Atlas、某名球员或某项指标而消失。观众模式解释当前发生了什么，分析模式补充证据与阶段。模型生成内容不能覆盖正式比分和裁判状态。

### 右下战术卡

保留所选球队或球员的统计。复核期间标明“比赛暂停 / VAR 复核中”；死球时间不累积为某队有效控球。第 116 秒 A1 捡球属于死球中的物理持球，不表示 A 队恢复比赛控球。

83 秒出球快照只在相关复核证据已到达、用户打开证据时展示。主球场不自动跳回 83 秒，用户也不会被强制切换镜头或播放位置。

## 4. 官方状态时间线

以下时间为片段内发生时间，也是预缓冲后界面的播放位置；对应比赛时钟需加 90 分钟。每项仅在其记录实际到达后显示。

| 片段时间 | 比赛时钟 | 可见事实 / 状态 | 提示文案 | 正式比分 |
| --- | --- | --- | --- | --- |
| 0–90 秒前 | 90:00–91:30 前 | 正常攻防 | 补时 +2；解说来自当前事实 | 0–0 |
| 90 秒 | 91:30 | s002 入网，待判 | 皮球入网，判罚待定 | 0–0 |
| 90.5 秒 | 91:30.5 | o001 延迟举旗 | 助理裁判举旗：疑似越位 | 0–0 |
| 92 秒 | 91:32 | d001 初判无效；v001 检查开始 | 初判越位、进球无效；VAR 复核中 | 0–0 |
| 99 秒 | 91:39 | v002 证据准备好；v003 请求场边复核 | VAR 已提供证据，主裁准备复核 | 0–0 |
| 104 秒 | 91:44 | v004 场边复核开始 | 主裁正在查看回放 | 0–0 |
| 114 秒 | 91:54 | v005 复核结束 | 复核结束，等待最终判罚 | 0–0 |
| 115 秒 | 91:55 | d002 撤销初判；g001 确认进球 | 进球有效，Union 取得领先 | 0–1 |
| 120 秒 | 92:00 | 片段结束，未重新开球 | 片段结束，比赛尚未终场 | 0–1 |

初判“进球无效”和“VAR 审查中”同时成立：前者是当前判罚，后者是审查状态。复核完成不等于改判，114–115 秒仍不能显示进球有效。

状态从当前已经可见的记录计算，持续到下一阶段。不能只扫描最近 30 秒的球员事件，也不能要求官方事件的 `team_id` 等于用户关注球队。d002 通过 `supersedes=d001` 替代初判的当前效力，初判历史仍在证据中保留。

第 72 秒的 d000 是允许合法铲断后继续比赛的判罚，不应因此进入 VAR 模式。

## 5. 入网与确认效果

第 90 秒可以显示“入网待判”和球员已有的真实轨迹；正式比分、确认进球的视觉效果等待最终判罚。无需补造裁判位置、三维裁判人物或球员追踪中不存在的动作。

确认时触发一次短暂庆祝效果，持续 4 秒：

- 触发依据为 g001 与 d002，确认收件时刻为 115080 ms。
- 本例效果开始于播放时刻 115000 ms，结束于 119000 ms；不能用 g001 的发生时间 90000 ms 计算效果年龄。
- 同一会话、同一回放轮次、同一确认事件只触发一次；重复 SSE 更新不重新播放。
- 暂停时效果进度随播放位置停住；后退后再次正常播过确认时刻，可以再次呈现。
- 直接拖到 117 秒，显示确认后的状态及效果对应进度；直接拖到 120 秒，不重新播放过期庆祝。
- 开启“减少动态效果”时，保留文字确认与比分变化，关闭弹跳、粒子及镜头缩放。

现有实现以 `now - event_time_ms` 判断进球是否新鲜。g001 到达时入网已经过去 25 秒，因此会漏掉解说和庆祝。新增效果必须区分足球发生时间与确认呈现时间。

## 6. 派生状态与消息边界

增加一个只消费已接收记录的裁判状态归约器，统一生成比分附近的提示、解说卡状态和证据引用。它不得加载设计文档或离线答案文件。

建议在现有 payload 上附加两个可选对象，保留旧字段供现有消费者使用：

| 对象 | 核心内容 |
| --- | --- |
| `playback` | 显示位置、片段时长、收件偏移、显示比赛时钟 |
| `review` | 当前阶段、当前判罚、涉及球员和球队、阶段发生与到达时间、证据 ID |

`review.phase` 使用明确的阶段：`none`、`pending`、`flagged`、`checking`、`review_requested`、`reviewing`、`awaiting_decision`、`awarded`。`current_decision` 独立表示尚无判罚、初判无效或最终有效，避免把“正在审查”误当成新的判罚结果。

正式比分继续由已获知的有效 goal 记录计数，不能把 shot_end、举旗、初判和最终判罚分别算成进球或重复加减分。

新增庆祝 cue 需声明使用播放时钟，并分别保留：事件发生时间 90000、获知时间 115080、呈现开始时间 115000、结束时间 119000、涉及球队 U 及 g001/d002 引用。前端和导出的叠加信息使用同一时钟定义。

## 7. 证据、统计与语言

- 官方事件校验增加 offside_flag、decision、var，明确球员动作主体为空、裁判 ID 与职责匹配、涉及球员与球队一致，保留 null/unavailable 的位置状态。
- 追踪中的 `in_play=false` 和空比赛控球队伍表示死球；不得回退到最后一次球员事件推定“Union 仍在控球”。缺失追踪与死球是不同状态。
- 普通传球链和球员指标跳过裁判记录，不能让 `team_id=null` 的判罚事件制造额外球权转换或打断球员传球链。
- 证据列表显示“主裁 / 助理裁判 / VAR”，而不是将官方事件当球员；事件详情保留原始 ID。
- 官方进程按获知时间组织，便于看到最新改判；同时保留事件发生时间。例如 g001 显示“91:30 入网，91:55 确认”，不能因其发生时间较早而藏到旧球员事件后面。
- 第 99 秒复核阶段关联的是第 83 秒出球快照 t166 / e025，不能把 90.5 秒举旗时的位置当成越位判断依据。
- 中文、英文、法文、西班牙文、阿拉伯文均增加对应的状态、官方事件及片段结束文案。截图当前为法语，不能出现缺失翻译键。
- 回放到确认前，不显示最终判罚文案、不展示未来证据，不把 92:00 当成终场或直接称为绝杀。

## 9. 验收条件

1. 点击底部 03，后端返回 stream-04 / match-04；按钮仍为 03，01/02/90′ 入口保持原行为。
2. 第三入口和“下一个案例”的选择顺序一致，切换后清除上一案例的判罚提示、效果和迟到响应。
3. 初始显示位置 0:00、比赛时钟 90:00、比分 0–0，并可见第一帧 22 人及球；末尾为 2:00 / 92:00。
4. 播放时长恰为 120 秒，界面不显示 90 秒或 120.08 秒；收件尾部仍完整接收最后一帧。
5. 抽查第 18、45.5、72.5 秒的球权转换，及 P23/P24/P25 三传反击，球与人物来自真实追踪记录。
6. 入网、举旗、初判、五个 VAR 阶段、最终判罚依次呈现；114 秒复核完成仍不提前显示有效进球。
7. 按原始收件截止时间 115079 ms 查询时比分为 0–0；115080 ms 时为 0–1，只计一次。
8. 确认时出现新鲜的解说与庆祝；重复数据包不重复计分或重启效果；关注 Atlas 时仍看到全局判罚。
9. 拖回确认前，比分、官方状态、证据和效果一起回退；再次播过确认时刻可以重新正确呈现。
10. 复核阶段显示比赛暂停，不把 VAR 时间或 A1 捡球算作有效比赛控球；官方记录不生成额外球权转换。
11. 证据正确关联第 83 秒的出球快照，保留事件与获知时间，五种语言无缺失键。
12. 120 秒时停止在片段末帧，显示尚未终场；不补造重新开球、终场哨或最终胜负。

验收覆盖独立状态单元检查、现有会话/API 链路、前端时钟与 cue 转换，以及浏览器实际播放和拖动。使用本地确定性事实模式完成，不需要调用模型 API。

## 10. 方案取舍

采用“第三位置切换数据源 + 官方状态派生”的方案，既满足底部编号要求，也保留新旧数据身份。相比覆盖旧 stream-03 文件，它能继续保存原来的缺失数据案例；相比增加一个第四案例按钮，它符合用户确认的第三位置替换范围。

保留现有页面布局，只增加紧凑状态和必要解说；不为这次接入重做球场、偏好面板或其他案例。可见内容来自当前记录，避免将设计中的未来结局写成预制解说。
