## Agent 工程保障

- 每次调查冻结数据；只能读取已发生且已到达的事件。评估标签不进入模型输入。
- 独立复核发布候选；被拒后只允许一次修订。无依据数字、越界窗口、未来证据、把夺回球权写成抢断等会被拒绝。数字匹配只是必要检查，语义正确性仍须独立模型复核和最终人工验收。
- 实时调查上限 14 次模型请求、24 次工具调用、25 秒总时间；单次请求 8 秒。回顾有独立的较长预算。
- 15 秒分批调查，并在射门结束、进球、换人、终场后触发；不是每一帧请求模型。
- 2 个执行线程，最多 8 个排队/执行任务；失败退避；同类任务去重。切换时间或偏好后取消后续调用，已经发出的请求结果也不会覆盖新状态。
- SQLite 记忆只读同一会话版本和当前时刻之前的记录。模型结果保留它真实的取证时刻。
- API 每次发送前单独校验授权。额度按授权批次持久化、跨进程原子扣减，重启不重置；旧凭据指纹拒绝复用；浏览器不能解除门禁。
- 离线事实叙事与真实模型输出分别标注。测试替身验证调度协议，不计为 AI 准确率。

## 本地视频的实际边界

这是可运行的本机预训练模型路径，不是只在彩色像素上工作的旧实验。旧的程序素材实验室仍保留，供时序事件回归测试。

视频需要可见球场和合理标定才能输出米制测量；镜头切换或标定失效时停止推断。球衣颜色用于队伍聚类，真实姓名需要绑定名单；匿名轨迹不冒充已确认身份。足球在空中的高度没有被建模，因此速度是二维投影采样/飞行均速，不是出脚瞬时速度。不会由一次射门推断进球，未提供比分时显示“未确认”。没有提供进攻方向时，进攻三区、前后向推进与射门分类不作猜测；不会将暂未识别到压迫解释为零压迫。

真实样片来自 [Roboflow Sports 官方示例](https://github.com/roboflow/sports/blob/main/examples/soccer/setup.sh)，仅留在 `run-output/` 本地验证，未打包发布。自动标定的 10 秒地面传递片段处理 126 个采样帧，诊断重跑用时 87.13 秒，自动提取出 **3 次传球和 1 次压迫**。传球距离估计分别为 12.64、15.88、9.75 米；第一脚传球飞行均速约 8.78 m/s，后两脚存在短遮挡，均速保留为空。数据已通过格式校验并接入正常 Session、统计、叠加层和回顾。

这是检测→跟踪→自动标定→事件→产品的实际模型运行结果，没有手工填入传球标签。此前相同片段只有 1 次压迫，修复了多个球场候选选择错误与相邻帧标定跳变后得到上述结果；原模型观测轨迹已保存成回归样例。完整原因与复现见 [视频诊断记录](VISION_DIAGNOSIS.zh-CN.md)。最终代码复跑用时 102.60 秒，仍得到相同的 3 次传球和 1 次压迫；已通过 HTTP Session→统计→Overlay→Recap 联测。结果保存为 `run-output/vision-acceptance/summary.json`。

**本机视频是离线预处理，不是实时广播解算。** 单片段成功不等于对任意广播镜头的准确率与召回率承诺；目前没有人工标注测试集支持这样的统计结论。传球、拦截、射门的时序行为另有受控轨迹回归。实时主路径按官方给出的合成事件接入需求运行。

比赛的实时主路径使用合成事件源，视频解算作为可取消的本地预处理任务。模型的源码/权重许可证与校验和记录在 `config/vision-model.json`，主检测器声明 AGPL-3.0，其他权重保留各自上游来源及条款提示。

## 可复现验收

```bash
python3 scripts/offline_acceptance.py
python3 scripts/api_acceptance.py
```

最新本机结果：四份数据集验证通过，76 项 Python 测试＋12 项 Node 测试全部通过。90 分钟比赛的 13,553 条记录分 136 批增量接入，接入＋确定性统计/发布 P95 为 83.12 ms、最大 138.06 ms；不包含真实模型推理或浏览器绘制，详见 `run-output/acceptance/live-arrival-latency.json`。

第一条执行数据验证、Python 行为测试、Node 行为测试并写 `run-output/acceptance/report.json`。第二条只生成验收计划，**不会调用模型**。

已经通过浏览器实际操作验证：导入 stream-03、58 秒缺口、Fan/Analyst 切换、比赛回顾、选择真实视频→本机分析→结果→同步叠加页。实际视频任务明确显示模型 API 0 次。

API 验收矩阵包含三个版本的中英文调查、球员聚焦、截至当前的回顾、全场回顾，共 9 个案例，最坏 146 次模型请求；可按单个案例逐步跑。必须在用户另行同意、提供新凭据、约定额度后执行。脚本不会自行授权。

API 阶段只测真实模型的选题、解释、证据对应、双语/受众差异、拒答和耗时；不能用 API 验收来掩盖未实现的接口，也不能用它代替视频精度评测。任何失败都应修复并重新验证，不以“代码存在”当作通过。
