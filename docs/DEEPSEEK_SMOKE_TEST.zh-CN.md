## 真实调用暴露的问题与已完成的修正

1. **调查不收敛、返回格式混乱。** 改为角色专属的完整 JSON 示例、逐轮预算提示、批量指标查询和重复事实复用。所有角色继续共享同一总预算。
2. **进攻方向理解反了。** 工具明确每队己方/对方球门 x 坐标，并返回球队视角的推进方向、朝球门位移和起终点实际距离。
3. **片段计数被扩大为全场、recovery 被描述为 tackle。** 补充范围与事件类型检查，同时允许正确的否定说明，避免把“不能代表全场”误拦截。
4. **缺失数据被扩散到其他通道。** 每个指标返回它实际依赖的通道覆盖；压力或位置缺失不等于夺回和射门事件也缺失。
5. **JSON 偶尔为空或无法解析。** 每角色最多重试一次，仍计入预算。保存的 02 运行中真实发生一次格式失败后恢复。认证、余额及网络错误不会无限重试。
6. **复核质量。** 调查采用非思考模式，Verifier 使用同一个 `deepseek-flash` 的 low 推理强度。模型返回的私有推理内容被丢弃，只保留外部动作、数值、审核意见与用量。

开发中共运行 17 次完整或中途降级的调查，累计 165 次模型请求尝试。保存的三次结果来自修正后的末轮；失败尝试的状态也保留在索引中。不能将挑选后的三次流程成功写成“首次成功率 100%”。

## 尚未解决的验收问题

**02 的距离表达仍可能误导。** `attacking_progress_m` 表示朝对方球门的纵向位移，`travel_distance_m` 是实际起终点距离。模型仍倾向用“向前传球 14 米”等短语混合两种含义，部分数字也只引用事件的派生字段而没有独立指标引用。应进一步限制非必要数字，或让前端直接用结构化字段渲染带明确单位的数值。

**03 存在实质性过度判断。** Analyst 文案将“Union 没有射门”扩写成“Atlas 是唯一有威胁的一方”。没有射门不证明没有威胁，这句话不被现有数据支持；Verifier 仍批准了它。因此 JSON 中的 `status:publish` 目前仅表示模型审核通过，不能当作人工语义验收通过。连接前端前需要去掉这类无指标支持的强弱比较，并建立包含同类反例的检查。

尚未实测全量偏好变化、跨时刻记忆、独立未见场景、并发负载或实时服务延迟。现有页面继续播放旧合成动画与解说；Microsoft Agent Framework 也尚未集成。

## 密钥与复现

密钥保存在权限为 `0600` 的 `.env.local`，已被 Git 忽略。代码、前端、运行记录和导出的评测文件中未发现该密钥。请求只发送到官方 HTTPS 域名，拒绝携带认证信息跟随重定向。

```bash
python3 scripts/run_harness.py data/streams/stream-01.jsonl \
  --provider deepseek --model deepseek-flash \
  --as-of-ms 68000 --language zh \
  --output run-output/result.json --trace run-output/trace.jsonl
```

重复运行可能得到不同的调查步骤和措辞。离线答案、审阅报告和保存的运行样本均位于模型工具不可读取的位置；运行入口不会加载这些文件。
