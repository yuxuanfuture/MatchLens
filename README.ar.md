يحوّل MatchLens أحداث كرة القدم المرصودة إلى تفسيرات مرتبطة بالأدلة وإلى ملعب مصغّر مخصّص. تتحول الحقائق نفسها إلى سرد موجز للمشجعين، وسياق كمي للمحللين، وإشارات متزامنة لطبقات البث.

## طريقتان للتشغيل

MatchLens إطار عمل قابل للتشغيل للأدلة والوكلاء، وليس مجرد فيديو توضيحي مُعدّ مسبقًا.

| الوضع | ما الذي يعمل |
| --- | --- |
| **دون اتصال** | معالجة حتمية للأحداث، وتحليلات، وأدلة، وإعادة تشغيل، وترجمة، وواجهة مستخدم. لا حاجة إلى نموذج أو مفتاح API. |
| **نظام متعدد الوكلاء مدعوم بـ API** | يقود DeepSeek أو Ollama المحلي الـ Coordinator والأدوار المتخصصة الاختيارية؛ وتبقى الأدوات الحتمية مصدر الحقائق الرقمية، بينما يراجع Verifier مستقل كل نتيجة مرشحة. |

يشترك الوضعان في نافذة المراقبة المجمّدة نفسها، وعقد الأدلة، وPocket Stadium، وفحوص النتائج القديمة. يستطيع النموذج التحقيق في المباراة وشرحها، لكنه لا يستطيع اختلاق السجلات أو تقديم ساعة الإعادة أو تجاوز ميزانية الطلبات.

## لماذا MatchLens؟

من السهل عدّ بيانات كرة القدم، لكن من الصعب تفسيرها. يربط MatchLens كل ادعاء بالأحداث أو سجلات التتبع التي تدعمه، ويحترم ما كان قابلاً للرصد في تلك اللحظة، ويعرض عدم اليقين بدل ملء الفجوات بحقائق مختلقة.

تكيّف الواجهة تدفق أدلة واحدًا مع وضعي Fan وAnalyst. اللغة الافتراضية هي الإنجليزية، مع دعم الصينية المبسطة والفرنسية والإسبانية والعربية، إضافة إلى متابعة فريق أو لاعب، وPocket Stadium قابل للإعادة، وطبقة بث شفافة.

## أبرز المزايا

- **الأدلة أولاً:** ترتبط التفسيرات بالسجلات المستلمة والمقاييس الحتمية؛ وتظل البيانات المفقودة مفقودة بدل تحويلها إلى صفر.
- **إدراك الإعادة:** يُفصل وقت الحدث عن وقت وصوله، فلا تكشف الإعادة هدفًا أو قرار VAR مستقبليًا.
- **التكيّف مع الجمهور:** يشترك وضعا Fan وAnalyst في الحقائق، ويختلفان في اللغة والكثافة والتركيز والعرض.
- **جاهز لتعدد الوكلاء:** يستطيع نظام اختياري محدود تفويض التحقيق، والتحقق المستقل من الادعاءات، وإهمال النتائج القديمة.
- **عرض محمول:** تعمل التجربة الأساسية محليًا باستخدام Python ومتصفح حديث من دون خطوة بناء للواجهة الأمامية.

## بدء سريع: دون اتصال

المتطلبات: Python 3.13 ومتصفح حديث. يلزم Node.js 22 فقط لاختبارات المتصفح.

### macOS أو Linux

```bash
python3 -m backend.server --port 43128
```

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\start-matchlens-windows.ps1
```

افتح <http://127.0.0.1:43128/?lang=ar>. يجب أن تبقى الخدمة المحلية قيد التشغيل لأنها توفّر تدفق الأحداث وواجهات الأدلة والتحكم في الإعادة.

## توصيل مزود نموذج

يتضمن المستودع محولات لواجهة DeepSeek الرسمية وخدمة Ollama على عنوان loopback المحلي. تفشل السياسة المضمّنة بشكل مغلق عمدًا، لذلك فإن إضافة مفتاح وحدها لا ترسل أي طلب. لتفعيل تحقيقات متعددة الوكلاء ومدعومة بـ API:

1. اضبط المزود محليًا: احتفظ بمفتاح DeepSeek في `.env.local` الذي يتجاهله Git، أو شغّل نموذج Ollama على `127.0.0.1`.
2. أنشئ تفويضًا صريحًا ومحدودًا في `config/model-policy.json`.
3. شغّل الخادم للتحقيقات المستمرة المجمعة حسب الأحداث، أو شغّل `scripts/run_harness.py` على لقطة مجمّدة من التدفق.

راجع **[إعداد API للنموذج (بالإنجليزية)](docs/MODEL_API_SETUP.md)** للحصول على أوامر DeepSeek وOllama وحقول السياسة وسلوك الميزانية وخطوات الإيقاف. لا تدخل الأسرار إلى المتصفح أو المطالبات أو سجلات التتبع أو الملفات الملتزم بها.

## العرض التوضيحي

السيناريو الأساسي عبارة عن تسلسل مدته 120 ثانية في الوقت بدل الضائع: تدخل قانوني يبدأ هجمة مرتدة، ثم تُرفع راية التسلل على انفراد، ويتقدم VAR إلى مراجعة على جانب الملعب، ولا يُحتسب الهدف إلا بعد أن يصبح القرار النهائي قابلاً للرصد.

جرّب التبديل بين وضعي Fan وAnalyst، وتغيير اللغة، ومتابعة لاعب، وفتح **See the evidence**، وإنشاء ملخص، والرجوع على الخط الزمني للتأكد من اختفاء النتائج المستقبلية.

## النظام متعدد الوكلاء

لا يحتاج المنتج إلى نموذج كي يعمل. عند تفعيل سياسة fail-closed صراحةً، يمكن استخدام أدوات الأدلة المجمّدة نفسها بواسطة نظام تحقيق متعدد الوكلاء ومحدود:

![بنية نظام MatchLens متعدد الوكلاء](docs/architecture/multi-agent-system-v3.svg)

الـ Coordinator وحده يستطيع التفويض. تخضع كل نتيجة مرشحة غير فارغة لمراجعة مستقلة، ويجب أن تأتي جميع الادعاءات الرقمية من الأدوات الحتمية، وتُهمل النتائج المرتبطة بموضع تشغيل أو تفضيلات أو نافذة أدلة سابقة. محولا DeepSeek وOllama المحلي اختياريان؛ وتعطّل السياسة المضمّنة استدعاءات النموذج افتراضيًا.

## التحقق

شغّل مجموعة القبول الكاملة دون اتصال:

```bash
python3 scripts/offline_acceptance.py
```

تتحقق من البيانات الاصطناعية، وتشغّل اختبارات Python واختبارات Node الخاصة بالمتصفح من دون إرسال طلب إلى API لنموذج. يشغّل GitHub Actions المسار نفسه عند كل push وpull request.

## بنية المشروع

| المسار | الغرض |
| --- | --- |
| `backend/` | خدمة الأحداث، والتحليلات الحتمية، وأدوات الأدلة، وAgent Harness الاختياري، ومهام الفيديو المحلية |
| `dist/` | Pocket Stadium، ومحرك العرض، والترجمة، وأدوات البيانات، وطبقة البث |
| `data/` | تدفقات اصطناعية قابلة لإعادة الإنتاج، وملفات تعريف، وخطط إشارات صوتية |
| `evals/` | النتائج المتوقعة للاختبارات وتشغيلات التقييم التاريخية الموسومة بوضوح |
| `scripts/` | توليد البيانات والتحقق وإعداد البيئة وأوامر القبول |
| `tests/` | اختبارات تراجع Python والمتصفح |
| `docs/` و`case-design/` | عقود هندسية وأدلة إعداد وحدود ومبررات السيناريوهات |

## الحدود والترخيص

- جميع الأندية واللاعبين والأحداث والمواقع والنتائج بيانات اصطناعية خيالية.
- لا يتضمن المشروع لقطات من الدوري الإنجليزي الممتاز، أو تدفق بيانات رسميًا، أو شعار نادٍ، ولا يدّعي وجود شراكة إنتاجية.
- مسار الفيديو الاختياري معالجة مسبقة دون اتصال، وليس عرضًا لاستدلال بث في الزمن الحقيقي؛ وتتطلب المسارات المجهولة ربطًا صريحًا بقائمة اللاعبين.
- لا يتضمن المستودع العام أوزان النماذج، أو تسجيلات مصدر من أطراف ثالثة، أو مسار الجمهور المولّد، أو البيئات الافتراضية الخاصة بجهاز معين.
